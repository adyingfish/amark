AI Agent 产物的第一位读者

写作正在交给 Agent，阅读依然属于你。

LLM wiki、本地知识库、迭代中的 PRD……它们通常有层级、有交叉引用，也会被一轮又一轮地修改。

AMark 把整个目录以所见即所得的方式渲染，并通过 Agent 写入状态提示与最近变更面板，让阅读过程保持连续。

设计原则是保持 AI Agent Native，同时坚持本地优先、轻量和开放格式。

搜索结果应当直接回到上下文，而不是让读者重新在长文中寻找刚才看到的那句话。

数据流与职责

当前文档搜索直接读内存中的活动文档；工作区搜索把查询交给 Rust 后端扫描文件，同时传入已打开且未保存的内容作为覆盖值。这样既不阻塞界面，也不会漏掉刚输入但尚未保存的文字。

入口

快捷键与菜单共用动作

在现有 menu_action 分发链中新增两个动作，避免菜单与键盘各维护一套行为。

  • Ctrl/Cmd+F：当前文档
  • Ctrl/Cmd+Shift+F：工作区
  • Escape：关闭或清空焦点

四段式交付

先固定纯函数和后端结果协议，再接 UI 与编辑器定位，最后做跨视图回归。每一段都有可独立验证的完成条件，避免把问题堆到集成阶段。

搜索核心

定义结果结构、行列与上下文生成；后端只扫描 Markdown，复用隐藏目录规则。

验证：Rust 单元测试

当前文档

实现查找条、上一个 / 下一个、循环导航、大小写选项，并覆盖四种视图模式。

风险与约束

最需要提前处理的不是“能否找到字符串”，而是富文本视图中的位置映射、未保存内容的一致性，以及连续输入时旧请求覆盖新结果。

风险 等级 处理方式 验证
Markdown 源码位置与富文本位置不同 中 当前文档按活动编辑面搜索；工作区结果在富文本中按可见文本定位，遇到仅存在于语法标记中的匹配则回退到源码视图精确定位。 粗体、链接、代码块、公式样例
未保存内容与磁盘结果冲突 中 前端只发送脏文档覆盖值；后端对同一路径优先使用覆盖内容，并校验路径仍在工作区内。 修改未保存、保存后、外部更新
快速输入导致结果闪回 低 150 ms 防抖；每次请求携带递增序号，只接收最后一次请求结果。 模拟慢响应与连续键入
大型目录扫描卡顿 低 spawn_blocking 后台执行，复用现有目录排除规则，并限制每文件 50 条、总计 500 条结果。 构造千文件工作区基准

范围边界

首版目标是把最常用的查找闭环做扎实。高级查询能力留到真实使用反馈出现后再决定，不在本次开发中预埋复杂抽象。

本次包含

  • 当前文档与整个工作区两种范围
  • 纯文本、默认不区分大小写、可切换大小写
  • 上一个 / 下一个、循环导航、结果计数
  • 工作区按文件分组、显示行号与上下文
  • 未保存文档、隐藏目录偏好、中英文界面

本次明确不做

  • 正则表达式、模糊搜索与拼音搜索
  • 替换、批量替换与搜索历史
  • 非 Markdown 文件与附件内容索引
  • 持久化倒排索引或后台常驻索引服务
  • 跨工作区与语义搜索

完成判定

下面这些行为全部通过，才视为功能完成；“界面能搜出示例文字”不等同于交付。

四种编辑视图中，Ctrl/Cmd+F 都能打开查找并定位当前匹配。
Ctrl/Cmd+Shift+F 会展开侧栏并聚焦工作区搜索输入框。
查询为空、无工作区、无结果、达到结果上限时均有明确状态。
点击工作区结果会打开正确文件，并定位到对应匹配。
未保存内容可被搜索，且不会同时出现磁盘旧内容的重复结果。
连续键入时不会显示旧查询的迟到结果。
隐藏目录行为与“显示隐藏文件夹”偏好一致，生成目录始终排除。
vp check 与 vp test 全部通过。
